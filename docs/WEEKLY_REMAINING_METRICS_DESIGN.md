## 3. `p_mastery` 环比候选（A/B/C）

### A. 最小向前时点快照（推荐，待确认）

未来在定期/周边界的同一数据库一致快照读取当前 `knowledge_states.p_mastery`，并记录**实际采集时刻**、
已应用 `apply_seq` 水位、算法版本与来源覆盖。它回答“该时点系统已处理的掌握度”；迟到分析只影响
后续快照，不改写、不伪造既往快照。缺业务周边界样本只能标记为缺失或 `unknown`，不能晚采后冒午夜
回填为当时值。无法追溯建立切换前或本方案启用前的历史边界。

### B. 按业务时间重估（重述指标）

把事件按 `occurred_at` 分窗，再按同用户 `apply_seq` 保持 BKT 原顺序重放。它可用于事后重述，但
不等同于各历史时点当时的 `knowledge_states`：切换后处理的历史 Job、迟到事件和 `legacy_unknown`
基线都会被纳入重估。响应必须带 `restated/as-of`，不得称为当时实时状态。查询时重放（无新持久化）
是此语义的实现变体，不是独立口径：实现快但每次报表成本高、迟到事件使已读结果变化，仍须声明
重述口径，只适合小规模诊断，不作为正式周报数据层。

### C. 保留当前 `p_mastery`、暂不做趋势（等待前向历史）

只展示当前值，不产生环比/趋势，直到启用方案 A 积累足够历史边界。改动最小、零口径风险，但无法
满足“环比趋势”目标，只作等待期过渡。

## 4. 报告窗口 / 对比窗口 / IANA 时区（均待确认）

现有“已记录会话时长”合同（`docs/WEEKLY_RECORDED_DURATION_CONTRACT.md`）以请求 `end_date + IANA
timezone` 返回“截至该日并包含该日的最近七个本地自然日”，UI 默认 `end_date=本地今天`，因此默认
视图是含今天的七个本地日桶，不是自然周。本卡不得因指标名称带“周”就把这个既有口径静默改成
自然周，也不能把实际采集时刻晚采后冒到周边界当作当时值。旧七桶口径完全不变。

- 报告窗口（本周）：候选（a）保持“含今天七桶”滚动窗口，与时长一致；（b）本自然周进行中（周一至
  当前日，含进行中尚未结束的周）；（c）最近一个已完成自然周（周一～周日，不含今天/当前未完成周）。
  （b）与（c）的区别是“进行中的自然周”含今天且边界尚未完整，而“最近已完成自然周”只取已封口的
  完整周。均待确认。
- 对比窗口（上一周期）：候选（a）紧邻的前一个七桶；（b）上一个自然周；（c）自定义 N 周。均待确认。
- IANA 时区：候选（a）沿用请求 `timezone`（用户本地）；（b）账号默认时区；（c）服务端固定 UTC。
  均待确认；时区决定“日桶/周边界”落点，跨 DST 或跨日会话的归属须显式声明。
- 推荐组合（待确认）：若优先与既有时长一致、改动最小，推荐“报告窗口=含今天七桶 + 对比窗口=
  紧邻前一个七桶 + 时区=请求 `timezone`”，旧七桶口径完全不变、无新增周边界语义；若优先稳定可比
  的自然周语义，推荐“报告窗口=最近已完成自然周 + 对比窗口=上一自然周 + 时区=账号默认/请求
  `timezone`”，但需新增自然周边界与完整周判定。取舍：前者是“保持既有窗口的改动最小候选”，复用
  现有口径、迁移最小，但滚动七桶始终是七个本地日，问题不在“缩水”而在“今天未结束”——当前七桶
  含进行中的今天、上一七桶已完整，须把进行中/未知标出，或后续定义等长观察进度，不能直接当作
  完整周期对比；后者边界稳定但需额外定义完整周与跨时区归属。两者均须用户确认并等待前向快照
  累积，不因选型即承诺已能计算趋势。
- 快照/采集时刻记录**实际采集时刻**；缺业务周边界样本只能标缺失/`unknown`，不能晚采后回填到
  午夜/周边界冒充当时值。

## 5. 主口径（百分点差 vs 增长率）

主口径推荐**百分点差**：`Δpp = 100 × (p_new - p_old)`，其本身无分母；只要两个 `p` 均可信可比，
`0→0.10` 就是合法 `+10pp`，不因起点为 0 而降为 `unknown`。来源覆盖不可比、窗口不完整、无真实
观察、基线 `legacy_unknown` 或算法版本不可比时仍须显示 `unknown`。相对**增长率**
`(p_new-p_old)/p_old` 是另一口径，仅在 `p_old=0` 时无法计算而显示 `unknown`；例如 0.40→0.50 为
`+10pp`、增长率 `25%`。`legacy_unknown` 可作为连续性起点，但其未知历史合成影响不能被后续重估
洗成纯真实历史；切换前趋势不可恢复。推荐方案 A 从启用后向前积累；若用户选择方案 B，只能显示为
按业务时间的重述值。

新增快照/读模型只是本次候选方案，不是已批准实现。若实施新增读模型，账号结构化导出与 B1-5
同事务整账号删除是**必须配套的实施前置**，版本兼容与重建/冻结规则一并设计，不能默认“不影响
这些合同”，也不能把导出/删除列为可豁免选项；未准备好这些配套时只能延期新增读模型。`apply_seq`
原顺序、B1 事件不变量、成功 Job 不回填和已定保留/删除政策均不变。

## 6. 其他指标拆分

- **发音准确率**：先定义分子/分母（音素正确/可评估音素、可映射观察、还是会话 overall_score）；
  真实 Provider 前返回 `unavailable`，合成只单独展示 demo 计数，不进真实准确率。
- **焦虑/语速**：`EmotionAnalyzer`（`backend/services/emotion_analyzer.py`）当前不足 2 条发言直接
  返回保守默认 `EmotionState`（`anxiety_level=0.3`、`hesitation_rate=0.0`、`wpm=0.0`），这不是
  真实评估；`transcripts.emotion_state` 只存四个规则值，无样本数/版本，不能从默认 0/.3 推断真实
  情绪。因此“不足 2 条→`not_assessed`”需列为待确认的新合同；存量 `emotion_state` 若来源/样本
  不明则显示 `unknown`，不伪造成历史。两者分列，不合并成健康分。
- **RAG 学习重点**：输出“目录推荐 + 理由/命中技能”，不称个性化质量或 Krashen 有效性；目录版本与
  检索排序入响应，真实教学效果另需人工/学习结果验收。
