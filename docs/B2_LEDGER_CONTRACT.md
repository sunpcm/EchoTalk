# B2 学习事件契约（新 main 增量版）

> 日期：2026-11-17。基线：`5d3641203484d66454a45f6d43547648b99dc05c`。
> 状态：S0/S1/S2 已独立 `APPROVED R1` 并本地提交；S3 已独立 `APPROVED R2` 且本地实现验证完成、
> 未 push/合 main/部署。本文不表示真实服务运行、生产、CI 或部署已完成。历史 B1 文档继续有效；

## 1. 范围

B2 为后续成功分析建立从空事件链起步的只追加学习事件，并在同一事务中更新当前知识
状态。新 main 已含 `learning_events`、writer、canonical、replay、历史 cutover、删除、
导出和 goals；本增量不重复建表，不改写 B1 历史迁移，也不另造平行服务。

S0 只固化当前 main 的 B2 口径。S1 只对已有 `learning_events` 做 ALTER 加固。S2 才适配
成功分析链，S3 才适配只读重算。S1 迁移写入不代表已执行；DDL 必须先经主控静态 Review，
再由主控在专用空库执行。

开发期不读取或承接旧测试 Job，不写 baseline，不从旧 Assessment、GrammarError 或
`knowledge_states` 回填，不迁移旧测试用户，也不对成功 Job 重新分析。新 Job 从
`p_init=.1` 建立新 B2 阶段。

历史 `learning_event_cutover` 表、维护入口和相关迁移保留，以维持现有源码、删除与导出
行为。B2 新成功链不以 cutover 阶段或 baseline 作为准入，该运行路径由 S2 落地。正式
retention、真实用户切换、数据清理、生产迁移与不可恢复删除不在本包批准范围。

## 2. 当前表与 S1 加固

新 main 的 `learning_events` 已有 24 列、6 个 RESTRICT 外键、主键、唯一约束和检索索引。
本包只保留并加固这些对象：

- `apply_seq` 从 `GENERATED BY DEFAULT AS IDENTITY` 改为
  `GENERATED ALWAYS AS IDENTITY`，不重置序列、不改已有值。
- 保留 `idempotency_key` 全表唯一及 `analysis_job_id` 的完成事件部分唯一索引。
- 保留 `user/session/job/source` 外键和既有索引；不删列、不删外键、不删索引。
- 新增 `idempotency_key <> ''`、`source <> ''`、
  `provider IS NULL OR provider <> ''`。
- 新增 `details` 顶层必须是 JSON object 且 `schema_version` 为数值 `1`；比较必须包成
  `(... ) IS TRUE`，不能让 JSON 类型未知值或 SQL `UNKNOWN` 穿透。
- 新增 `algorithm_params IS NULL OR jsonb_typeof(algorithm_params) = 'object'`，同样包成
  `(... ) IS TRUE`。
- 替换旧 shape CHECK，使 completed、发音观察、语法观察和 baseline 的逐列形状固定。

加固后的 9 个 CHECK 为：

| 约束                                            | 语义                                 |
| ----------------------------------------------- | ------------------------------------ |
| `ck_learning_events_type`                       | 只允许四种冻结事件类型               |
| `ck_learning_events_confidence`                 | confidence 为空或在 `[0,1]`          |
| `ck_learning_events_snapshot`                   | snapshot 为空或在 `[0,1]`            |
| `ck_learning_events_idempotency_key_not_empty`  | 幂等键拒绝空串                       |
| `ck_learning_events_source_not_empty`           | source 拒绝空串                      |
| `ck_learning_events_provider_null_or_not_empty` | provider 允许 `NULL`，拒绝空串       |
| `ck_learning_events_details_shape`              | details 为 object 且版本为数值 1     |
| `ck_learning_events_algorithm_params_object`    | 参数为 SQL `NULL` 或 JSON object     |
| `ck_learning_events_shape`                      | 每种事件关联字段、来源字段和布尔形状 |

`analysis_completed` 必须 `source='analysis'`。mapped 发音和语法观察必须同时有非空
`observation_code` 与 `model_version`，且 `model_version <> ''`。语法观察必须
`observation_correct IS FALSE`。completed 与 baseline 的空字段规则沿用冻结 B1 语义。

已有非法行必须让升级在事务中失败并整体回滚。迁移不得 UPDATE、DELETE、TRUNCATE、
SETVAL、补 `"unknown"`、删行或自动降级约束。downgrade 只移除本包 5 个新增 CHECK、
恢复旧 shape 和 `GENERATED BY DEFAULT`，不碰其他表、列、索引、外键、历史值或历史
revision。

## 3. 事件与完整批次

四种事件保持冻结：

| 类型                        | 每个成功 Job        | 含义                                    |
| --------------------------- | ------------------- | --------------------------------------- |
| `analysis_completed`        | 恰好 1 条           | 完成标记、coverage、unmapped 与算法事实 |
| `pronunciation_observation` | `0..N`              | 一个可映射的原始发音位置                |
| `grammar_observation`       | `0..N`              | 一个已持久化的语法错误，始终是错误观察  |
| `baseline_snapshot`         | 当前 B2 writer 0 条 | 仅为历史兼容保留                        |

幂等键冻结为：

```text
analysis_completed         job:{analysis_job_id}:completed
pronunciation_observation  job:{analysis_job_id}:pron:{source_ordinal}
grammar_observation        job:{analysis_job_id}:grammar:{source_ordinal}
future baseline            baseline:{cutover_revision}:{user_id}:{skill_id}
```

`attempt_count` 不属于键。失败重试与 stale recovery 复用同一 Job 和键；成功后的重新
分析未开放。

一个完整批次是一条 completed，加本次规范来源集合中全部可映射观察。所有行必须属于
同一 user、Session、Job，来源必须属于同一 Session，Job 最终为 succeeded。completed
存在而观察缺失、观察无 completed、额外观察、跨 Job 混搭或半批均 fail closed；不得补
局部事件、重复应用 BKT 或把已有全局键当作成功证明。

写入前必须先固定本次完整期望集合：一条 completed，加上规范来源集合中每一个可映射
观察对应的稳定键。不能从实际写入结果或已有事件反推期望集合，也不能在发现缺失、额外
或不可纳入项后删除期望项再宣称成功。比较必须覆盖完整集合；子集相等不构成完整批次。

首次插入与冲突重读执行同一套比对：在插入前先固定完整规范键集合和不可变 payload，逐项
核对 user、Session、Job、来源关系、事件类型、技能、位置、布尔/代码、来源事实、时间、
details、算法版本与参数；任一缺失、额外、重复或字段不一致都整批拒绝。不能因为键尚未
冲突就跳过 payload 校验，也不能用已有 completed 行替代完整批次证明。

冲突重读与来源核验必须在锁定 Job、Session 所属 User 的事务内进行；数据库中的最新 Job
仍须为 `running`，Job、Session、User 和每个来源的归属仍须一致。锁外读到的事实不能作为
最终准入依据。

## 4. 锁与事务

S2 的目标成功链为：

```text
锁 Job
→ 执行评估并 flush 来源行
→ 读取 Session
→ 锁 Session 所属 User
→ 在锁内重读并核验 Job 仍为 running
→ 校验所有来源归属
→ 写 completed 与完整观察批次
→ 更新真实非合成 BKT
→ 置 Job succeeded
→ commit
```

User 锁覆盖首次状态创建、事件写入、派生更新和 Job 成功。仅锁 Job 不能串行化同用户
两个 Job；仅锁已有 `knowledge_states` 也不能阻止首次创建竞争。任一失败或取消整体
回滚。

当前 main 的 writer 顺序含历史 control 行：`control → Job → User`。B2 新成功链退出
该 control 依赖后，writer 为 `Job → User`；现有账号删除路径可能为 `User → Job`。
S2 必须在改运行代码前设计兼容锁序或统一控制锁，并用真实 PostgreSQL 并发测试证明
删除、失败重试、stale recovery 与 writer 不会死锁或互相绕过。S1 只登记风险。

## 5. 规范顺序与来源事实

发音观察的 `source_ordinal` 固定为 `phoneme_alignment` 原数组下标。不可映射项不入
观察，保留位置空洞，不压缩、不按 UUID 重排。

语法观察按 `(skill_tag, error_type)` 排序并分配规范位置。同一稳定键重复必须拒绝，
不能依赖数据库未排序返回或随机 UUID 决胜。writer 与 replay 必须共享同一纯规范规则。

每用户事件顺序由用户锁内写入的 `apply_seq` 决定。全局 sequence 可有空洞，不代表跨
用户提交顺序；`recorded_at`、业务正文、Provider 时间和随机 UUID 不能替代。

## 6. 七键 coverage

completed 的 `details.coverage` 每个方向固定七键：

```text
status
reason
result_count
reused
metadata
basis
source_facts
```

七键的类型和条件固定为：

| 键             | 类型与条件                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| `status`       | 字符串，只允许 `not_called \| evaluated \| failed`；completed 中只允许前两者                               |
| `reason`       | 字符串，取 I1 `CoverageReason` 的真实调用原因                                                              |
| `result_count` | JSON integer 且 `>= 0`，或 JSON `null`                                                                     |
| `reused`       | JSON boolean                                                                                               |
| `metadata`     | JSON object 或 JSON `null`；保留 I1 的真实 metadata，`null` 不表示缺失可被重写                             |
| `basis`        | 字符串，只允许 `current_invocation \| persisted_rows \| none`                                              |
| `source_facts` | JSON `null`，或恰好包含 `source/provider/model_version/is_synthetic` 四键的对象；各值按真实事实可为 `null` |

`status/reason/result_count/reused/metadata` 来自 I1 当次调用事实，`metadata` 必须原样保留
调用级事实。`evaluated` 必须使用 `basis=current_invocation`，其 `source_facts` 按完整来源
集合分两种情形投影：锁定 Session 中存在持久化来源行时，必须取该方向全量、同质来源行的
四事实，不要求调用级 `metadata` 与逐行事实相同；真正零来源的合法调用（例如语法零错误）
则从本次调用 `metadata` 投影 `source/provider/model_version/is_synthetic` 四键。两种情形都
不能因行集合为空而把 `source_facts` 改成 `null` 或 `basis=none`，也不能把调用级 metadata
覆盖成逐行事实。`evaluated` 的 `result_count` 必须非空并与完整来源一致：发音等于
`phoneme_alignment` 原数组长度，语法等于持久化语法来源行数；语法零错误因此为 0。

复用已有结果仍表示当次没有调用，即 `status=not_called`；只有
从锁定 Session 的全量、同质来源行证明历史评估完整时，才可同时写
`basis=persisted_rows` 和可核验的 `source_facts`。`basis=none` 只用于固定来源集合确实没有
可纳入项的未调用方向，此时 `source_facts` 必须为 JSON `null`。`persisted_rows` 不得混用
不同来源、Provider、版本或合成标记的行，也不能用一条 `LIMIT 1` 样本证明整个方向完整。

`source_facts` 的对象值可空，不能伪造 `"unknown"`；`provider=null` 是合法来源事实。不得把
正文、纠错文本、音素对齐、Provider 原始响应或提示词写入 `source_facts`。metadata 的 JSON
`null` 必须原样保留。`failed` 只进入非提交诊断，不得写进 completed；异常或取消必须让 Job、
事件和 BKT 整体回滚。

writer 在删除或过滤任何期望项之前，必须先固定两方向完整来源集合与完整期望观察集合，再逐一
覆盖并核对规范键、来源身份和不可变 payload。已有 mapped 来源但版本未知/空串、来源异质、
归属不明或完整性无法证明时，必须整批拒绝；不能删掉证据不足项后以 `basis=none`、
`unmapped=0` 伪成功。没有来源与“有来源但不能安全纳入”必须严格区分。

零语法错误表示 `grammar.status=evaluated` 且 0 条观察，不能写一条正确语法观察。
未配置、已评估零错误和评估失败必须区分。全合成批次仍保存事件，但不读、不建、不改
`knowledge_states`。

来源集合必须双向完整核验：Session 中全部规范来源都在固定期望集合中，固定期望集合中的
每一项也都仍存在于该 Session。既不能漏掉数据库新增来源，也不能使用已删除、跨 Session
或无法证明归属的来源。

## 7. `bkt-v1`

版本固定为 `bkt-v1`，参数固定且恰好为四个 JSONB 数值键：

```text
p_init=0.1  p_transit=0.2  p_slip=0.1  p_guess=0.2
```

真实、技能有效的观察按 `apply_seq` 重放；合成观察跳过。状态和参数必须是有限数值，状态
必须位于闭区间 `[0,1]`；`1e-9` 只用于比较实际状态与重算状态，不能放宽参数值或输入边界。
初始状态固定为 `p_init=.1`，干净起步不使用旧 baseline。答对时：

```text
p_correct = (1 - p_slip) * p + p_guess * (1 - p)
posterior = (1 - p_slip) * p / p_correct
p_next = posterior + (1 - posterior) * p_transit
```

答错时：

```text
p_incorrect = p_slip * p + (1 - p_guess) * (1 - p)
posterior = p_slip * p / p_incorrect
p_next = posterior
```

参数、公式或算法实现变化必须使用新版本，旧事件不原地改写。

真实更新前，writer 只检查本批参与非合成 BKT 更新的技能。若其中任一技能已有
`knowledge_states` 行，必须在同一用户锁和事务内证明该状态有更早的真实 B2 历史：
至少一条非合成发音或语法观察，其对应 Job 已成功、completed 事件使用 `bkt-v1`，并带完整
七键 coverage。历史观察所在方向的合法证明有两种：当次调用为 `evaluated/current_invocation`，
或当次复用已存结果而为 `not_called/persisted_rows`；两种都必须有与真实同质观察一致、
`is_synthetic=false` 的 `source_facts`。不得把 `not_called/persisted_rows` 改写成
`evaluated`，也不得把调用级 `metadata` 当作逐行 BKT 事实。查询必须显式排除当前
`analysis_job_id`，不能让本批刚插入的事件反过来证明旧状态。旧 baseline、五键旧 completed
或任意无支撑状态都不是当前 B2 初值，必须整批 fail closed，不清理、补录、回填或改写状态与
事件。

同一门禁还必须识别反向损坏：本批技能没有 `knowledge_states`，但排除当前 Job 后存在合法
真实 B2 历史时，不得从 `p_init=.1` 重建，必须整批 fail closed。只有“既无旧状态、也无真实
B2 历史”的技能才从 `p_init=.1` 起步；有上述真实历史的后续更新才可沿用当前状态。全合成
批次仍保持对 `knowledge_states` 的零读取。同一批技能的状态与历史均使用集合查询，不能退化
为逐技能读取。此处只建立起点与历史门禁，每次更新的完整数值重放留给 S3。

## 8. S3 一致快照

replay 在任何数据查询前执行：

```sql
BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ READ ONLY
```

首条数据查询固定 watermark：

```sql
SELECT COALESCE(MAX(apply_seq), 0) FROM learning_events
```

后续只读同一快照且只处理 `apply_seq <= watermark`。watermark 后提交属于后续快照，
不能误报。干净起步意外出现 baseline 应报告 `unexpected_baseline`，不能静默作为起点。

报告只读，结尾 ROLLBACK。不得修事件、状态或 Job。S3 必须在同一快照中校验每个成功 Job
的完整批次、全量来源、事件集合和状态集合：成功 Job 缺 completed、completed 缺观察、
额外观察、缺状态或额外状态均须报告；观察必须覆盖完整规范批次，不能只抽样检查。问题码必须
稳定并可供测试精确断言。S3 稳定问题码至少覆盖：

```text
canonical_key_mismatch       event_schema_version_mismatch
completed_source_mismatch    coverage_mismatch
missing_source               ownership_mismatch
completed_job_mismatch       event_time_mismatch
unexpected_baseline          duplicate_completed_event
algorithm_mismatch           event_order_violation
canonical_source_invalid     unexpected_observation
canonical_order_mismatch     missing_observation
mismatched_batch             unmapped_count_mismatch
missing_completed_event      real_state_missing
synthetic_state_drift        state_mismatch
state_out_of_range
```

算法版本固定 `bkt-v1`，四参数精确为 `p_init=.1 / p_transit=.2 / p_slip=.1 /
p_guess=.2`；版本或任一参数与冻结事实不符均报 `algorithm_mismatch`，调用方传入的
registry 不得覆盖该冻结事实。unmapped 计数必须是严格非布尔、非负整数。发音 alignment
为 `None` 时保留既有语义；非 `None` 必须为合法有序数组，`[]` 有效；非法 falsy JSON
（如 `{}`、`false`、`0`、空字符串）不得被静默当作零观察，须报 `canonical_source_invalid`。
跨来源观察的实际 `apply_seq` 顺序须与规范观察批次逐位置一致，否则报
`canonical_order_mismatch`。

并发测试须使用两条真正独立的连接和可重复等待的因果屏障，记录并断言
`watermark 返回 < writer 提交 < observer 后续读取`。测试必须在 watermark 查询返回后才
通知 writer 提交，再通知 observer 执行后续读取；不能把普通 sleep、事务开始时间或未等待的
并行调用当成因果证明。没有可证明顺序时保持未验证。

## 9. 相邻能力

新 main 的本人数据导出、整账号删除和 goals 保留。B2 不新增 API、不改删除/导出政策，
也不把现有路由复制到平行实现。账号删除仍须联动删除本人事件、来源与派生状态；导出
仍须保留来源、合成标记、版本和 coverage 等审计事实，排除密钥、内部提示词和 Provider
完整原始响应。

本轮不批准真实 retention。生产备份中的删除/到期、法定或特殊保留、恢复后不复活已删
数据，仍需独立方案与验收。

## 10. 与 B1 历史的关系

B1 的 cutover、baseline、旧 pending/failed Job 和七项政策继续作为历史记录与现有源码
事实保留。B2 当前选择是从新 main 的干净开发期事件链起步：

- 不承接旧 Job、旧状态或旧事件；
- 不写 baseline、不回填、不重新分析成功 Job；
- 历史 cutover 表/迁移保留，但不作新成功链准入；
- S2 代码与测试已独立 `APPROVED R1`、S3 已独立 `APPROVED R2`，本地实现验证完成、
  未 push/合 main/部署；真实服务运行、生产与 CI 未执行，不声称新链已上线运行。

本契约的 S1 可执行边界仅为
[`b2_ledger_hardening.py`](../backend/alembic/versions/b2_ledger_hardening.py) 和相应模型、
测试。S2/S3 的范围见 [B2 实施计划](./B2_IMPLEMENTATION_PLAN.md)。
