## 3. B2 五问（原推荐 / 备选 / 已确认选择 / 剩余门禁）

### 3.1 基线切换方式

- 事实：`knowledge_states` 是累积后当前值，无法还原历史观察/顺序；`legacy_unknown` 不是真实历史。
- 原推荐 / 未来备选（时点基线锚定）：维护窗口停旧写 → 每 `(user_id, skill_id)` 写 `baseline_snapshot(source=legacy_unknown)` → 部署事件写入门控 → 恢复流量。代价：需一次短维护窗口与写入门控；剩余门禁：一致性快照/幂等/补处理另设计。仅在未来真实用户切换获批时再评估。
- 备选（清空重建）：语义简单但用户看到回退，且无法自证起点。
- 已确认（2026-11-16，开发期）：干净起步，丢弃旧测试数据与资料，从 `p_init=.1` 开始新事件链；不保留旧知识
  状态基线，不回填历史。必要的课程/技能种子与结构保留。时点基线仅作为未来真实数据场景的备选。

### 3.2 旧 pending / failed Job

- 事实：Job 对 session_id 唯一；failed 只走现有 `can_retry_job` 人工重试，无自动重启/清 attempt_count/新 run；当前无「取消」状态。
- 原推荐 / 未来备选（切后统一事件事务，failed 沿现有人工重试）：切换时 running 先排空/回滚再取一致基线；旧 pending 在切点后经统一事件事务处理（`occurred_at` 可能早于切点，不称历史回填）；failed 仍只沿现有 `can_retry_job` 人工重试（保留预算与错误资格）。代价：需实现「运行中排空/回滚」与「切点一致」门控；不新增停用状态、不自动全部重启。仅在未来真实数据切换获批时再评估。
- 原备选 / 未来备选（切换前排空旧 Job）：排空可仅靠维护门控与等待完成，不引入新状态；若需显式停用/取消，才需当前不存在的状态或另定策略（可能丢失用户失败重试意图）。仅在未来真实数据切换获批时再评估。
- 已确认（2026-11-16，开发期）：旧测试 Job 不承接，旧测试数据可丢弃；干净起步后的新 Job 走统一事件事务。
  不批准切点后的历史处理或回填，也不表示任何 Job 清退操作已经执行。

### 3.3 retention（含删除 / 导出）

- 事实：设计列 A（账户存续期保留）/ B（固定窗口+快照）/ C（短窗口硬删）；无已实现删除/导出路径。

## 4. 周报指标口径（用户已确认 / 实现仍待办）

### 4.1 已实现（不改）

最近七自然日 completed 会话次数、按日只读历史、语法 Top3（rolling7 + started_at 归属；0 转录 completed 计 1）。

### 4.2 已确认口径（指标实现仍待办）

- **辅助时长（首期只命名「会话经过时长」）**：`ended_at - started_at`，不叫「有效练习」。口径：仅 completed 且 ended_at 非空；0 转录/未进房会话不单独区分（保持现状计 1）；跨日归属按 `started_at`；负值/缺失按异常不入时长或单独标记；时区按本地自然日窗口，保持当前 rolling7。真正有效练习时长需媒体/说话区间输入，B2 建表不自动可算。
- **掌握度环比（推荐「同技能百分点变化」）**：`p_mastery` 是概率，用百分点差而非百分比增长率；同版本（bkt-v1）+ 真实来源（is_synthetic=false）+ 缺值不入 + 可比基线（快照门控）写清；不能用 recorded_at 当提交时间、不承诺过两周必有有效历史。只有当前值无法恢复历史；B2 事件不足以自动定义自然周末快照，趋势快照/补处理/完整性需另设计。
- **发音趋势 / 焦虑 / 语速 / 下周重点**：逐项列出所需输入（当前无法承诺可算）：
  - 发音趋势：需真实发音评估结果（当前 demo_mock），无真实输入前不可算。
  - 焦虑/语速：需语音声学或时长切片（当前无持久化用户说话区间，timestamp_ms 非音频分段）。
  - 下周重点：依赖掌握度环比与真实评估，需先有可比历史。
- 未来完整自然周与现有 rolling7 不相互覆盖（两者并存，不覆盖既有口径）。
