# CP-05 设置抽屉可用性（A21）

## 1. 基线与范围

A20@2adbe4b之后，仅修改SettingsDrawer.tsx、styles.css、zh-CN.ts；可新增SettingsDrawer.test.tsx和e2e/settings-drawer.spec.ts。不改App/store/API/auth/平台/依赖锁/原生工程/后端/已有E2E或runner。实际双浏览器基线320x568/667x320/960x720：无dialog语义、打开焦点在背景、Escape不关闭、关闭按钮28x28；未复现水平溢出，不能虚构。

## 2. 模态与资源所有权

抽屉按已打开的设置交互提供可命名dialog、modal语义，打开聚焦内部合理控件（避免自动聚焦API Key调起键盘），Tab/ShiftTab留在对话框内，背景不能被鼠标/键盘激活。Escape、关闭按钮和真正遮罩区域点击关闭，内部点击/输入不关闭；关闭后焦点回到仍存在的原触发控件。普通store更新或onClose新闭包不能重置焦点、关闭/重开、清草稿或解除背景保护；StrictMode/卸载幂等清理。按现有目标浏览器可优先采用平台原生dialog以降低维护成本，无新依赖；实现形式可判断，不能只有aria-modal无行为。

打开时防背景滚动且面板自身可滚动；关闭/卸载恢复原先滚动样式，不写全局主题/其他用户设置。使用原生顶层模态能力时不手动留下其他页面inert，监听与scroll lock只清理自身拥有资源。关闭/resize/Tab/Escape本身零PUT、登出、创建、恢复或其他业务写操作；显式保存/主题操作维持原有行为。

## 3. 尺寸、视口与输入

320px竖屏、667x320横屏、桌面缩小、根字号200%时无横向内容截断/溢出；设置关闭、模式开关、主题与保存操作点击区域至少44x44 CSS像素。面板不超可用动态视口，使用dvh及合理fallback/安全区padding，顶部关闭及底部表单/保存可经面板滚动达到，不以overflow-x:hidden掩盖内容缺失。关闭控件可持续到达，toast不盖住关键按钮；输入焦点与滚动不丢草稿。文案通过i18n。浏览器resize只模拟可用空间变化，不冒充真实iOS键盘或非零safe-area硬件验收。

## 4. 验收与边界

补组件回归（jsdom缺原生dialog行为时仅测试生命周期调用，不把polyfill当浏览器证明）和Chromium/WebKit真实页面E2E：命名modal/焦点、双向Tab/Escape恢复、遮罩/内部点击、健康重渲染保留、44触控区域、窄屏横屏/200%/缩高后滚动保存可达、开关关闭零隐式写。保留所有原产品/构建/22浏览器回归，并将新E2E接入默认七门禁；不得弱化已有断言/skip或修改Fake API以制造绿灯。

不安装/扩CLI权限/真实Provider/IdP/Xcode/设备操作/push/deploy。下一阶段真实键盘、锁屏、蓝牙与系统回跳需独立设备证据。本轮仅共享设置界面，不将全局响应式或三端整体勾选完成。
