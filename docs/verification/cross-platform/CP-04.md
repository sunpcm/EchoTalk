# CP-04 跨平台本地认证状态与账号清理验证规范

## 1. 目标与范围

根据 `docs/CROSS_PLATFORM_AUTH_LIFECYCLE.md` 契约，本阶段重点解决跨平台客户端本地认证生命周期管理、账号切换清理与并发数据隔离：

1. **认证快照与代际防护（AuthSnapshot & Revision Fencing）**：引入 `AuthPrincipal` 与单调递增的 `authRevision`，确保 401 退出只影响当时发起请求的 revision，不误伤后来新登录的会话；
2. **初始化重叠与事件淘汰机制**：引入独立的 `activeInitSequence`，新启动的初始化立即淘汰先前在途的旧初始化；期间发生退出或事件变更亦淘汰旧初始化，杜绝旧请求先返回抢占或覆盖较新初始化结果（P1-1 修复）；
3. **Redirect Callback 单次交换共享与操作级来源隔离（R3、R4 & R5 修复）**：针对每次 redirect callback 操作创建独立的公有 `UserManager` 实例与绑定该操作所有权（`initSeq` + `authRevision`）的 `userStore` 包装；当 StrictMode 或重复调用 `initializeAuthSnapshot()` 处理同一个 `(code, state)` 时，共享同一个尚未结束的在途 callback 交换操作，确保只消费一次 `state`、只交换一次 authorization `code`。即使该在途交换期间因 `invalidateAuthSession` 或新账号 `UserLoaded` 失去了写入与发布所有权，在它尚未结束前对同一 `(code, state)` 的重复初始化也只观察该在途交换并返回当前最新快照，绝不重新消费已消费的 `state` 或授予新所有权从而误把已登录的新账号置为 `misconfigured`。在途交换结束后立即释放引用，不永久缓存 Token、`User` 或回调结果；不同 callback、退出或新登录/新认证事件拥有独立所有权，过期 callback 绝不写入 SDK `userStore` 或发布旧身份；
4. **原始精确身份提取**：`extractPrincipalFromUser` 保留原始未经 trim 归一化的 `iss`/`sub`，仅用 trim 检查非空，杜绝包含空格等变异的 subject 被错误合并（P1-2 修复）；
5. **账号切换完全重置**：不同 principal 切换时，必须同步清理所有用户 store（conversation, settings, assessment）及本地组件状态（通过 key 重挂载完全卸载旧 App 树），且不泄露上一账号草稿或主题配置（P1-3 修复，通过真实 React state 变更杀死删去 children key 变异）；
6. **同账号平滑续期**：同 principal 的 Token 刷新/续期不触发销毁和清理，不打断活跃语音通话；
7. **异步 Store 代际隔离**：settings 与 assessment 在 reset 时递增独立代际编号，丢弃在途旧请求的成功、失败及 finally 回填，避免覆盖新账号数据；
8. **本地只读主题样式**：App 启动仅对齐 DOM 属性，不向后端发送 PUT 请求；保留主动设置的主题防抖同步；
9. **纯公有接口、类型安全与真实单调清理保护（R2 & R4 修复）**：移除生产代码中迁就测试替身的特判、不安全类型强转及对 SDK `_userStoreKey` 私有字段的访问，完全使用 `oidc-client-ts` 公有接口与可赋值类型；`AtomicWebStorageStore` 记录写入时的 revision，旧 revision 发起的迟到清理绝不删除更新 revision 写入的凭据。

> **真实范围与未验证项声明**：本轮仅覆盖共享客户端可本地独立验证的认证状态机、StrictMode 单次 callback 交换共享、操作所有权隔离、账号切换清理、迟到响应门禁及 401 受控退出。真实 IdP 联调、原生系统认证/Keychain 存储、自动续期、跨客户端账号关联、WebKit 实机/浏览器与外部环境端到端验收不在本轮范围，均列为未验证项，不宣称 CP-04 整体完成。

## 2. 验证矩阵

| 验证项                                    | 验证方式   | 覆盖文件/组件                         | 预期行为                                                                                                                                                                                             |
| :---------------------------------------- | :--------- | :------------------------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Principal 精确校验**                    | 单元测试   | `auth.ts`, `auth.test.ts`             | 仅从 OIDC profile 提取非空 `iss`/`sub`，保留原始精确值，键采用 JSON 数组编码避免歧义碰撞                                                                                                             |
| **重叠初始化门禁**                        | 单元测试   | `auth.ts`, `auth.test.ts`             | 两个重叠 init 先启动者被淘汰，后启动者获胜；旧 init 在退出后完成绝不复活登录态（杀死门禁变异）                                                                                                       |
| **Callback 单次交换共享与操作所有权隔离** | 单元测试   | `auth.ts`, `auth.test.ts`             | 真实 SDK 公有入口下，同 `(code, state)` 重复初始化只消费一次 `state`/交换一次 `code` 并共享结果，结束后释放；不同 callback、退出、新登录拥有独立所有权，旧 callback 不写 storage 不发旧身份（R3/R4） |
| **Revision 失效机制**                     | 单元测试   | `auth.ts`, `auth.test.ts`             | `invalidateAuthSession(expectedRevision)` 仅使当前 revision 匹配时失效，旧 revision 幂等忽略                                                                                                         |
| **公有接口单调 Storage 清理**             | 单元测试   | `auth.ts`, `auth.test.ts`             | 不依赖私有 `_userStoreKey`，`AtomicWebStorageStore` 同步清理消除微任务间隙，旧 revision 清理不删除新 revision 写入的凭据                                                                             |
| **401 受控退出**                          | 单元测试   | `api.ts`, `api.test.ts`               | 401 只让发起该请求的 revision 失效；取得 Token 期间 revision 改变则在 fetch 前中止并抛出 i18n 错误                                                                                                   |
| **不同 Principal 切换**                   | 组件测试   | `AuthGate.tsx`, `AuthGate.test.tsx`   | principal 变更同步执行 `clearUserSessionData()` 并通过递增 key 卸载重挂载 children（测试真实 React state 杀死 key 变异）                                                                             |
| **同 Principal 续期保活**                 | 组件测试   | `AuthGate.tsx`, `AuthGate.test.tsx`   | 同 principal 的 Token 更新不重置组件，不清理 store，保持音频和草稿                                                                                                                                   |
| **Settings 异步代际隔离**                 | Store 测试 | `settings.ts`, `settings.test.ts`     | reset 递增代际，在途 fetch/update 迟到结果与错误不回填，主题防抖绑定 generation                                                                                                                      |
| **Assessment 异步隔离**                   | Store 测试 | `assessment.ts`, `assessment.test.ts` | reset 递增代际，两阶段 refreshAnalysis、retry 及 knowledge 在途迟到响应丢弃                                                                                                                          |
| **启动主题无自动 PUT**                    | 组件测试   | `App.tsx`, `App.test.tsx`             | App 挂载仅执行 `applyThemeAttr`，不调用 `updateUserSettings` 发送 PUT 同步                                                                                                                           |
