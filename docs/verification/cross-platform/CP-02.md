## B4：Cloud 单端通话占用协议（2026-10-21）

基线 `3b8b3ce8e22710160d14af80f0be786d0cae8d1b`；实施完成，停 Review。

落实 `docs/CROSS_PLATFORM_CALL_LEASE.md` 完整权威契约：

- 配置与模式：
  - 新增 `CALL_LEASE_MODE` 配置项，仅允许 `disabled`（默认）或 `livekit_cloud`。
  - `disabled` 模式保持既有 token/dispatch/end 行为，三个新占用写接口返回 503 `call_leases_disabled`。
  - `livekit_cloud` 模式必须具备非空 `LIVEKIT_API_KEY`/`LIVEKIT_API_SECRET` 及无凭据/query/fragment 的 HTTPS/WSS `*.livekit.cloud` 域名；自建 URL 拒绝启动；启动校验错误不回显秘密。
  - CORS 显式允许 `X-Call-Device-Id` 与 `X-Call-Generation` 请求头，保留严格未知头拒绝，不放宽通配符或 Origins。
- 占用数据模型与迁移：
  - 新增 `call_leases` 表（一用户一行），`user_id` 为主键及外键；包含 `session_id` (可空外键)、`device_id` (可空 UUID)、`generation` (非负 BigInteger 初始 0)、`state` (`held`/`free`)、`expires_at` (可空带时区 UTC 时间戳)。
  - 单条线性 Alembic 迁移 `c03_call_leases`，以 `c02_create_idempotency` 为父版本，降级仅删除 `call_leases` 表。
- 租约接口与接管顺序：
  - `POST /api/sessions/{session_id}/call/claim`：同 owner 重复 claim 保持 generation 并续期 90 秒；其他 held owner 在 `takeover=false` 时 409 `call_in_use`；在 `takeover=true` 时**严格先成功撤销旧 owner 的 Cloud Token，再更新 DB 授予新 owner 并递增 generation**；撤销失败 502 `call_provider_unavailable` 且不更新 DB。
  - `POST /api/sessions/{session_id}/call/heartbeat`：仅匹配当前 held owner 且未过期可续期；旧代际/非属主 409 `call_lease_lost`，过期 409 `call_lease_expired`。
  - `POST /api/sessions/{session_id}/call/release`：匹配 held owner 时先撤销 Cloud Token 再置 free；同 tuple 重复 release 幂等返回 200；旧 tuple 在新 owner 接管后 409 `call_lease_lost`。
  - 写接口在成功响应前执行显式 `commit`，commit 失败不返回成功。
- 门禁保护：
  - `GET /sessions/{session_id}/token` 与 `POST /sessions/{session_id}/dispatch` 在 Cloud 模式下要求 `X-Call-Device-Id` 与 `X-Call-Generation` 头；缺头 409 `call_lease_required`，失占 409，过期 409。
  - Cloud 模式 Token identity 固定为 `<user UUID>:<generation>`，room 为 session UUID，TTL 截断至租约剩余有效期（至多 60 秒，剩余不足 1 秒拒绝签发）；不持久化 Token。
  - dispatch 操作设置聚合 3 秒超时保护。
  - end 接口持有租约时先撤销 Cloud Token 并置 free，撤销失败 502 且整个事务回滚；重复 end 保持幂等单 AnalysisJob。
- 并发控制：
  - 所有 Cloud 操作统一按 User 行锁 (NOWAIT) → lease → Session 顺序；并发冲突通过结构化 SQLSTATE 55P03 精确映射 409 `call_lease_busy`，不使用文本模糊匹配。
- 模拟 Cloud SDK：
  - 基于本机 `livekit-api` 1.1.0 现有 `RemoveParticipant(RoomParticipantIdentity(room=..., identity=..., revoke_token_ts=floor(UTC now)+30))` 协议字段，不新增依赖，测试中严禁真实联网。
