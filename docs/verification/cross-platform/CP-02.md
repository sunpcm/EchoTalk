## B2：创建会话可选幂等（2026-10-21）

基线 `409b73548fe1a65a88b05cce0109a04404dbef4b`；实施完成，停 Review。

`POST /api/sessions` 增加可选 `Idempotency-Key` HTTP 头（规范化 UUID）：

- 缺省头保持既有每次新建会话行为；非法 UUID 字符串返回 400。
- 按已认证 `user_id` 与规范化 `Idempotency-Key` 隔离；对 Pydantic 规范化请求体（含 `mode` 及 `doc_context` 默认字段）计算稳定 SHA-256 请求指纹。
- 同用户同 key 且请求体一致返回原会话（即使会话已 completed 也不新建）；同 key 不同请求体返回 409。
- DB 层在 `sessions` 表新增可空列 `request_idempotency_key` (UUID) 与 `request_fingerprint` (String(64))，并增加 `uq_sessions_user_idempotency_key` 唯一约束。
- 并发使用 savepoint（`begin_nested()`）安全捕获精确唯一约束冲突后重新查询，不吞掉非目标异常；`doc_chat` 模式下 `SessionContext` 同事务只建一次。
- 单条线性 Alembic 迁移 `c02_create_idempotency`，基线父版本 `b3f1c8e92a10`，无用户输入拼接，具备完整 upgrade/downgrade。
- 跨域配置：在 `backend/config.py` 的 `CORS_ALLOW_HEADERS` 显式允许列表中新增 `Idempotency-Key`，保留未知请求头严格拒绝边界（不使用通配符 `*`，不改变 `CORS_ORIGINS`），确保 Web 浏览器跨域预检 OPTIONS 正确放行。
- 测试覆盖真实 PostgreSQL + httpx.ASGITransport，包含无 key 重复新建、串行重放、并发同步起跑防挂死、确定性双 miss 屏障真实冲突验证（同 body、不同 body、doc_chat 单 Context）、请求体变动 409、mode/doc_context 差异与默认值、跨用户隔离、非法 key 400、completed 重放、doc_chat context 唯一性、未认证 401 拒绝、非目标 DB 错误冒泡，以及 CORSMiddleware 预检回归测试。

## B3：活动会话只读发现（2026-10-21）

基线 `bdae64f9cbe982d73453b12e74237284481f9d19`；独立 Review APPROVED。

`GET /api/sessions/active` 落实 §8.4 只读发现接口契约：

- 返回当前已认证用户 `status=active` 的 `SessionListItem` 数组，按 `started_at desc, id desc` 确定性排序（含时间戳相同时按 UUID 降序保证确定性）。
- 空记录返回 HTTP 200 与空列表 `[]`；缺失或无效认证返回 401。
- 路由显式声明于动态 UUID 详情路由 `GET /sessions/{session_id}` 之前，确保 `/api/sessions/active` 正确匹配且不影响详情与 `/sessions` 历史列表。
- 响应字段最小化（仅 `id`, `mode`, `status`, `started_at`, `ended_at`），绝不泄露 Token、转录记录、文档正文、用户 ID 或幂等内部列。
- 严格纯只读：不签发 Token、不调度 Agent、不调用 Provider、不执行数据库清扫/更新。
- 契约明确：返回 active 仅代表数据库记录状态，不证明 LiveKit 房间存活或客户端拥有通话占用。
- 测试覆盖真实 ASGI + 专用 PostgreSQL 测试库：多用户隔离、completed/cancelled 排除、空列表 200、同时间戳确定性排序、响应字段最小化校验、未认证 401、历史及详情路由共存，以及读前后数据库记录无修改快照验证。
- 专用测试 fixture 随机生成用户并仅清理自身数据，退出时严格还原 dependency overrides。未 push/部署。
