# CP-05 主题持久化可靠性与稳定选择器（A28）

本轮实施基于 TODO.md P2“主题保存后端支持跨设备水合”与“统一主题按钮边框宽度，消除选中时 1px 布局抖动”契约。客户端保持 local-first 体验，完善了认证代际与精确身份绑定、单在途合并、水合竞争防护及 2px 固定边框无抖动选择器。

## 实现细节

1. **即时应用与认证状态门禁**：
   - 切换主题时即时更新 store、`<html data-theme>` 与 localStorage，保持 local-first 体验，失败不回滚 UI。
   - 主题同步绑定发起时的 settings 代际（`settingsGeneration`）与认证精确身份（`issuer` + `subject`）及 `authRevision`。
   - 匿名、加载中（loading）或配置错误（misconfigured）状态仅保留本地偏好，绝对不向后端发送 PUT 请求。
   - 直接在 300ms 防抖计时器触发的副作用前严格复核代际与身份，防止异步延迟把旧操作升级为新身份权限。

2. **单在途与待发最新意图串行合并**：
   - 同一身份下，主题 PUT 请求严格保持单在途（single in-flight），防止后端并发旧写覆盖新写。
   - 在途期间的快速切换操作保留 300ms 防抖并合并为待发最新意图（pending intent），在当前在途请求完成后自动串行推进。
   - reset 或换号操作立即清空待发意图并将旧在途请求孤儿化，新身份不被旧永不返回的请求死锁；旧请求的 finally 绝不清除新操作的槽位。
   - 主题同步仅 PUT `{ theme }`，不重放任何其他设置或凭据。旧 theme-only 响应仅合并更新 store 中的 `theme` 字段，绝不覆盖更新的通用设置保存结果（Provider、验证状态、API Key 存在标志等）。

3. **水合竞争防护**：
   - 严格消除 GET 与本地显式选择之间的竞争：若存在尚待同步的明确本地选择（防抖中、在途 PUT 中、待发意图或未完成同步），或者 GET 在途期间用户显式切换了主题，GET 返回时绝对不能覆盖本地选择。
   - 有效无冲突的 GET 请求正常水合至 store、`<html data-theme>` 与 localStorage。

4. **稳定选择器与固定 2px 边框**：
   - `SettingsDrawer.tsx` 中的三个主题按钮无论选中（active）与否，统一使用固定 `border-2`（2px 边框），消除此前 1px 边框差异导致的布局抖动。
   - 在桌面默认字号、窄屏移动端（390px）以及 200% 大字号布局下，选择切换前后下方内容垂直坐标位移差为 0px，无抖动。
   - 更新过期注释，明确 local-first 与跨设备水合说明。
