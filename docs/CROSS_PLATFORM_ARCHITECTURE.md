## 3. 首版默认策略

- 交付范围为 Web、iOS、macOS；Android/Windows 后置。
- 前台练习为基线。中断时停止或暂停采音，回前台先核对身份和服务端状态，再提示恢复。
- 不承诺后台持续通话、离线 AI 或实时跨设备语音接力。
- 历史、报告、学习状态和设置通过服务端共享；不把登录 Token 和实时房间内存状态跨端同步。
- 同一语音会话默认单设备占用；新设备必须显式接管，旧设备不能自动重连抢回。
- 本地最多保存恢复所需的非敏感标识；使用前重新认证并核验资源归属，退出时清理。

这些为实施默认值；产品策略发生变化时先更新决策和验收标准。

## 4. 网络与构建契约

| 项目         | Web                                    | 原生客户端                                     |
| ------------ | -------------------------------------- | ---------------------------------------------- |
| REST         | 默认同源 `/api`                        | 明确配置 HTTPS API origin                      |
| LiveKit 信令 | 当前默认同源 `/livekit-ws`，可配置直连 | 当前默认使用 Token API 的 `ws_url`，可强制代理 |
| 媒体连接     | 验证 ICE/TURN 和真实网络               | 同样验证，WSS 通不代表音频媒体链路通           |
| 配置         | Web 环境独立构建                       | 平台、测试/生产环境独立构建并校验              |

CP-01 需修正当前 API 地址无条件追加 `/api` 的行为，统一处理尾斜杠、已有前缀和非法 URL。
原生代理地址必须来自真实 API origin，不能来自 WebView localhost。
生产 HTTPS/WSS 限制不影响显式本地开发配置；不得以关闭全局 ATS 代替网络配置修复。

共用源码不要求共用同一个带环境变量的二进制产物。构建必须检查 Vite 环境加载、
Turbo 缓存输入、输出目录与 Capacitor `webDir` 一致性，防止同步其他端/其他环境的 dist。
`VITE_*` 为公开构建配置，不能保存 Provider 密钥、client secret 或长期 Token。

## 5. 认证与恢复契约

Web 保留现有 OIDC Code + PKCE；iOS/macOS 原生容器通过系统认证会话/系统浏览器授权，
由平台注册的回跳返回客户端。回跳同时覆盖冷启动与运行中应用，并验证 state/nonce/PKCE。

原生长期凭据使用 Keychain，短效访问凭据尽量驻留内存；续期采用单次并发协调。
Web 本轮先完善现有方案的过期与 401 处理，BFF/HttpOnly Cookie 作为独立架构决策，
不在本轮隐含改造。认证失败不自动重放非幂等写请求。

后端继续按 `(issuer, subject)` 识别用户。多 OIDC Client 必须核实 subject 策略：
若 IdP 使用 pairwise subject，先制定安全的账号关联方案，禁止按 email 自动合并。

统一恢复顺序：验证登录态 → 查询会话/设备占用 → 查询房间/Token → 用户确认恢复音频 →
重新拉取分析与报告。重试过程中避免重复创建会话、重复 Agent dispatch 和并行轮询。

服务端需补齐创建/结束幂等、设备占用与过期释放；客户端本地断开应立即停止采音，
服务端状态更新失败需明确展示并支持补偿，不让“结束请求失败”导致持续录音。

## 8. 下一轮冻结契约（2026-10-21）

### 8.1 CP-02 创建请求幂等

POST /api/sessions 保持现有请求体、200响应与鉴权边界；可选 `Idempotency-Key` HTTP头采用UUID（解析后规范化）。缺省头保持既有每次新建行为；非法UUID返回400。仅在头存在时启用幂等，不改变已有客户端。

按本地已认证user_id与规范化key隔离；同用户同key且规范化请求体一致返回原SessionResponse，即使原会话已结束也不创建新会话。规范化请求体为Pydantic校验后的mode及完整doc_context默认值，稳定JSON的SHA256指纹；同key不同请求体返回409。默认不自动删除key，随session保留。不同用户相同key相互隔离，不返回其他用户数据。

唯一约束保证并发只创建一条Session及至多一条对应Context；冲突处理不得使整个请求事务进入失效态，不吞掉非唯一冲突异常。服务端不缓存LiveKit Token、不会在重放时调用dispatch。新增列均nullable以兼容历史数据和无key请求；单条线性Alembic迁移以b3f1c8e92a10为父。此改动仅本地专用测试库迁移，不发布；新旧后端混跑未承诺，正式上线前单独规划迁移/回滚。

### 8.2 CP-01 构建与iOS同步

既有pnpm build默认产物dist保持兼容；新增显式平台命令产物独立存入dist/web/<mode>、dist/ios/<mode>。mode仅development/staging/production；平台仅web/ios，本轮不构建macOS正式业务壳。每个产物有不含秘密的标识manifest，至少记录platform/mode/API origin/auth mode。

构建读取app目录对应Vite mode的公开配置及显式process.env覆盖，不意外继承根.env；VITE\_\*均为公开配置，不纳入秘密。生产/预发布iOS构建要求有效HTTPS API、OIDC模式及必要OIDC配置，拒绝开发认证Token；development明确允许本机开发配置。未提供真实环境配置时保留未跑状态，验证可使用明确标记的example.test无联网值，但不得称为实际可登录产物。

iOS同步只接受匹配platform=ios及mode的已成功构建产物，验证失败、目标缺失或web产物必须在调用cap sync前拒绝，禁止静默回退旧dist。不修改ATS或签名配置，不运行Xcode编译、真机或联网SPM。脚本测试应使用临时目录及模拟child-process，另由评审验证真实构建和本地cap sync；生成的原生配置必须和webDir一致。

Turbo缓存显式包含影响构建的公开环境变量、根构建控制变量及相关脚本/配置输入；输出同时覆盖默认dist和平台子目录。新增命令优先使用现有Node/pnpm/Capacitor，不新增依赖、锁文件或env密钥文件。

### 8.3 单端通话范围（用户决策，2026-10-21）

同一账号在Web、iOS、macOS之间同时只允许一端通话；另一端必须由用户明确接管。旧端失去占用后不得自动抢回。不将设备占用等同于sessions.status=active；历史遗留active记录不证明LiveKit实际连接。租约、Token撤销/房间隔离、过期释放及接管接口须另行冻结契约并验证，当前阶段尚未落实此约束。

### 8.4 CP-02 下一增量：结束时本地释放及活动记录发现

客户端发起结束时，在等待HTTP响应之前卸载LiveKitRoom并清除内存Token/URL。使用独立ending/end_failed状态展示提交中及“本地音频已停止、服务端结束待重试”；仅服务端确认结束才进入分析视图。失败后只允许用户显式重试同一session的幂等end，不自动重连/恢复采音；在途结束去重。重置/返回主页或开始新操作后，旧异步health/create/token/end结果及旧setActive回调不得复活旧房间或覆盖新会话。新文案纳入i18n；当前不实现创建重试、持久化恢复或设备租约。

后端新增GET /api/sessions/active，返回当前已认证用户status=active的SessionListItem数组，按started_at降序、id降序确定性排序；空数组为200，缺认证401。该路由置于动态UUID详情路由之前；保留既有GET /sessions完整历史及详情行为。不得含Token、转录或文档正文，不更新状态、不签Token、不dispatch、不调用Provider。不引入迁移/分页/过期清扫；此接口只发现数据库活动记录，不宣称房间存活或客户端拥有通话占用。
